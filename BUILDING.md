# Building butMail

butMail 0.5 builds the GTK 4/libadwaita sources in `src/`.

## Fedora

Install the build dependencies using graphical authentication:

```sh
pkexec dnf install gcc vala meson ninja-build desktop-file-utils gtk4-devel libadwaita-devel webkitgtk6.0-devel libsecret-devel libsoup3-devel gdk-pixbuf2-devel evolution-data-server-devel rpm-build
```

Build and install:

```sh
meson setup ../butMail-builds/dev --prefix=/usr
meson compile -C ../butMail-builds/dev
pkexec meson install -C ../butMail-builds/dev
```

Configure mail accounts in GNOME Online Accounts. The application ID is `io.github.IzsakiRobi.butMail`; settings, keyring entries and local mail caches use that identity.

## RPM

From a source checkout, create an archive of a committed release and build the binary RPM:

```sh
mkdir -p ../butMail-builds/rpm/{SOURCES,SPECS}
git archive --format=tar.gz --prefix=butMail-0.5/ v0.5 > ../butMail-builds/rpm/SOURCES/butMail-0.5.tar.gz
cp packaging/butMail.spec ../butMail-builds/rpm/SPECS/
rpmbuild -bb --define "_topdir $(realpath ../butMail-builds/rpm)" ../butMail-builds/rpm/SPECS/butMail.spec
```

Runtime library dependencies are generated by RPM. The 0.5 release is built for Fedora 45 x86_64; older Fedora versions may not provide the required libraries.

## ARM64 RPM

The manually triggered **ARM64 RPM** GitHub Actions workflow builds on a native
`ubuntu-24.04-arm` runner inside a Fedora 45 container. It installs the spec's
build dependencies, builds only the binary aarch64 RPM, verifies the package and
ELF architecture, installs its runtime dependencies and checks shared-library
resolution. No mail account or graphical session is used.

Download the `butMail-fedora45-aarch64` artifact from the completed workflow run.
It contains the RPM and `SHA256SUMS`; artifacts expire after 14 days. The workflow
does not publish releases. A successful packaging check does not replace manual
GUI/account testing on ARM64 Fedora.

## User data

The source repository and release packages contain no mail, credentials or personal settings. GNOME Online Accounts must be configured again after reinstalling the OS. To preserve local settings separately, back up the dconf path `/io/github/IzsakiRobi/butMail/` and the app's directories under `~/.local/share/` and `~/.cache/` as needed.

Recipient suggestions combine system address books with mail-header history. At most 2,000 history entries are kept privately in `~/.local/share/io.github.IzsakiRobi.butMail/recipient-history.gv`; contact-only entries are loaded from EDS rather than persisted as history. Successful sends and recently selected recipients rank above passive mail-header matches. To/Cc/Bcc fields show up to eight suggestions after two characters, support multiple recipients and preserve quoted display names. Sent-folder headers are prepared asynchronously when opening a composer; suggestion collection does not download message bodies.

## Avatar sources

Avatars are resolved asynchronously in this order: enabled system address books (EDS photos), Gravatar, Logo.dev with the saved key, AnyLogo, CompanyEnrich, then the native monogram. Company-logo queries use the registrable domain from libsoup’s public-suffix database, never the full email address. The remote-avatar preference controls all external providers. A shared request cache avoids duplicate lookups; normalized images are stored privately under the app cache for seven days, and missing results are cached in memory for one hour.

[AnyLogo](https://anylogo.dev/docs/logos/) is the first keyless logo fallback, followed by [CompanyEnrich](https://companyenrich.com/free-tools/logo-api). AnyLogo requests do not force PNG; any image format supported by GdkPixbuf is accepted, without requiring an alpha channel. Raster logos, including JPEGs, must be square and at least 48 × 48 pixels. Each avatar additionally requires enough source pixels for its logical size times the display scale (84 × 84 at 2× for the 42 px avatar). Raster decoding only downsizes, capped at 256 px; square SVGs render losslessly at 256 px. Cache keys use the native-v2 namespace to exclude older images that may have been enlarged during decoding. Small or rectangular results are rejected. CompanyEnrich’s observed 128 px grayscale initial tiles (uniform #ddd background and centered dark letters) are rejected on download and cache reads, preserving the native colored monogram. A 429 response pauses requests to that provider for one minute without blocking the other provider. CompanyEnrich advertises a 500,000-request monthly fair-use limit without specifying its scope; the client does not register for a paid plan. Failed lookups fall back to the native monogram. Provider-specific cache keys prevent reuse of the previous provider's logos.

[Logo.dev](https://www.logo.dev/products/logo-api) is requested with `fallback=404`. [Gravatar](https://docs.gravatar.com/avatars/php/) uses the SHA-256 hash of the normalized address and `d=404`; neither provider's generated placeholders replace the app's native monogram.

## Notifications and background operation

Inbox monitoring follows Camel folder changes with a 60-second refresh fallback. Existing unread messages set the dock badge but do not produce a startup notification flood. Each new unread message has a stable notification ID; reading, deleting or moving it out of the Inbox withdraws the notification. Pending IDs are stored privately in `~/.local/share/io.github.IzsakiRobi.butMail/notifications.gv` so they can be reconciled after restart. Notification clicks open the matching conversation.

Unread Inbox totals are published with the Unity LauncherEntry D-Bus protocol supported by Dash to Dock and compatible docks. GNOME's unextended dash does not display this badge. Notification delivery and presentation follow the desktop's notification and Do Not Disturb settings.

Run in Background keeps monitoring after closing the main window and creates a per-user autostart entry under `~/.config/autostart/`. Disabling it removes that entry; Quit exits explicitly. The `--background` option starts without showing the main window and exits immediately when background operation is disabled. No renderer or system notification-service overrides are used.
